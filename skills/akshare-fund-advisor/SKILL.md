# AKShare 基金参考咨询

## 目标

将用户的自然语言问题映射为少量稳定命令，查询 AKShare 后提供可核验的基金参考信息。重点解决：

- 不知道基金代码或 AKShare 参数时，按名称、代码或拼音搜索。
- 判断当前处于历史高位、低位还是中间区域，并说明判断依据。
- 对可明确匹配的宽基指数补充 PE/PB 估值分位；不能匹配时不伪造估值。
- 提供专业终端式指数历史 PE/PB 双图、统计线和极值信息。
- 给出“值得买、继续定投、降低定投、等待、分批减仓”的条件式参考。
- 生成基础定投、减量、暂停追价或小幅估值倾斜等动作区间。
- 比较多只基金，但不把不同类型基金粗暴合成一个总分。

本 Skill 只提供金融信息分析和风险提示，不执行交易，不承诺收益，不给“必买、必卖、满仓、抄底”等确定性指令。

## 首次运行

Skill 目录记为 `SKILL_DIR`。优先使用 Skill 自带虚拟环境：

```bash
bash "$SKILL_DIR/scripts/setup.sh"
```

安装完成后统一通过以下入口调用：

```bash
bash "$SKILL_DIR/scripts/run.sh" --help
```

若网络或上游接口失败，必须明确说“当前无法确认”，不能把查询失败解释为暂停申购、暂停赎回或休市。

## 工作流

### 1. 识别用户意图

按下列顺序选择动作：

| 用户意图 | 动作 |
| --- | --- |
| 不知道代码、只给了简称或主题 | `search` |
| 问能不能买、能不能卖、高低位、是否适合定投 | `analyze` |
| 明确问暂停申购、限购、赎回或交易时段 | `status` |
| 问指数估值、历史 PE/PB、专业估值图 | `valuation` |
| 问几只基金怎么选 | `compare` |

用户只给模糊名称时先搜索。存在多个份额类别或多个近似结果时，列出候选并让用户确认，不能擅自替用户选择 A/C 类、ETF/联接或人民币/美元份额。

### 2. 执行最小命令

搜索：

```bash
bash "$SKILL_DIR/scripts/run.sh" search --query "纳斯达克"
```

只查询申购、赎回等业务状态：

```bash
bash "$SKILL_DIR/scripts/run.sh" status --fund "000001"
```

分析单只基金，默认观察最近 3 年：

```bash
bash "$SKILL_DIR/scripts/run.sh" analyze --fund "513500"
```

生成 10 年指数 PE/PB 图表数据：

```bash
bash "$SKILL_DIR/scripts/run.sh" valuation \
  --index "沪深300" \
  --years 10
```

比较 2 到 5 只基金：

```bash
bash "$SKILL_DIR/scripts/run.sh" compare --funds "000001" "110022"
```

审计真实接口：

```bash
bash "$SKILL_DIR/scripts/run.sh" audit
```

除非用户明确指定观察周期，否则基金分析使用 3 年、指数估值图使用 10 年。独立使用说明见 [USAGE.md](USAGE.md)，系统设计见 [DESIGN.md](DESIGN.md)；指标定义与专业解释必须阅读 [references/professional_metrics.md](references/professional_metrics.md)；详细接口映射见 [references/akshare_api.md](references/akshare_api.md)；指数图表必须继续阅读并遵循 [references/valuation_chart.md](references/valuation_chart.md)；接口审计方法与历史记录见 [references/interface_audit.md](references/interface_audit.md)。

### 3. AKShare 指数估值图

用户提到“指数估值、历史 PE/PB、深度资料、专业终端式展示”时，必须执行 `valuation`，不能只返回 `analyze` 中的估值摘要。

数据源规则：

1. PE TTM 只调用 AKShare `stock_index_pe_lg` 的 `滚动市盈率`。
2. PB 只调用 AKShare `stock_index_pb_lg` 的 `市净率`。
3. 只支持 `INDEX_CATALOG` 中有精确 AKShare 映射的指数；不做模糊替代。
4. PE 或 PB 单侧失败时只展示通过校验的一侧；两侧都失败时返回错误。

图表默认包含：

- PE TTM 和 PB 上下两张历史曲线。
- 当前值、历史分位、均值、中位数、最高、最低。
- 3/5/10/20 年可用窗口的独立分位，禁止 PE/PB 简单平均。
- 均值 ±1 标准差、20% 和 80% 分位参考线。
- 完整日频统计和最多 600 个显示点；显示点保留首尾、最高和最低。
- 3/5/10/20 年区间、实际数据起止日期和来源说明。

用户明确要求图表或可视化时，调用 `TRAE-dynamic-ui` 的 `PureShowWidget`，使用 `panel` 模式按 `chart_spec` 渲染。不得自行编造曲线点或修改统计值。

### 4. 解读“能买能卖”

默认将“能买能卖”理解为**现在买卖是否划算、处于高位还是低位、该如何分批或定投**，必须执行 `analyze`。只有用户明确询问暂停申购、赎回、限额或开市时间时才以 `status` 为主。

判断顺序：

1. **投资者约束**：资金期限、每期现金流、目标仓位、应急资金和最大可承受回撤。
2. **产品适配性**：基金类型、跟踪标的或业绩基准、经理、费用、规模和持仓集中度。
3. **持有体验**：年化收益、当前/最大回撤、回撤修复时间、最长水下期、下行波动和滚动收益分布。
4. **真实指数估值**：若 `index_valuation.available=true`，分别解释其固定 10 年窗口 PE TTM 和 PB；需要 3/5/10/20 年分位时，继续执行 `valuation` 并读取 `charts.<metric>.window_statistics`，禁止简单平均。
5. **历史位置与趋势**：解释 `history_position_percentile`、距高低点和 20/60/250 日均线；净值位置不是估值。
6. **场内溢价**：ETF 溢价过高时，即使指数估值不高也不应直接追价。
7. **操作状态**：申购、赎回、限额和交易时段放在结论之后，作为能否执行的约束。

`history_position_percentile` 只是历史净值或价格位置，不是估值分位。只有 `index_valuation` 中的 PE/PB 分位才能称为估值分位。

### 5. 形成参考咨询

回答按以下结构组织，缺失字段直接省略：

1. **位置结论**：一句话说明历史位置、估值位置（如有）和趋势，不先讲开市时间。
2. **买入参考**：直接解释 `decision_reference.buy`，说明适合等待、基础定投、小额分批还是提高定投。
3. **卖出参考**：直接解释 `decision_reference.sell`；没有成本和仓位时，只给再平衡条件，不猜用户盈亏。
4. **定投方案**：展示 `dca_plan.current_action`、频率、暂停条件和资金前提，不给机械倍数。
5. **关键数据**：数据日期、年化收益、下行波动、回撤修复、最长水下期、PE/PB（如有）、历史位置和场内溢价。
6. **产品与执行风险**：说明基金类型、经理、费用、规模、持仓集中度、业绩基准、申购状态、QDII 时差及数据缺失。
7. **待补信息**：询问持仓成本、当前仓位、计划持有年限、每期预算和最大可承受回撤，然后才能讨论具体金额。
8. **来源与时间**：注明 AKShare 接口、上游来源和查询时间。

不能只看高低位：

- 历史低位但趋势持续向下：可以分批观察，不能直接称为“抄底机会”。
- 历史高位但真实估值不高：可能是盈利增长推动，不能仅因净值创新高卖出。
- 估值高、历史位置高且场内溢价高：优先控制追高风险。
- 基金策略失效、经理变化、费用过高或资产配置不再需要时，即使低位也可能不值得继续定投。

场内基金必须检查 `premium_rate_pct`：

- 溢价明显为正时，提示场内价格高于 IOPV/净值，避免只因涨势追价。
- 折价不等于无风险机会，还要考虑 IOPV 时效、跨市场时差、申赎限制和流动性。
- AKShare 原始列名可能是“基金折价率”，脚本已统一按 `(价格 - IOPV) / IOPV` 计算；正数始终表示溢价。

### 6. 数据约束

- **最高优先级：模型严禁自行生成、猜测、补齐、插值或改写任何净值、价格、PE、PB、收益率、回撤、限额、日期或交易状态。**
- 所有定量事实必须逐字来自脚本 JSON；脚本失败、字段为 `null` 或数据过期时，只能回答“当前无法确认”。
- 回答前必须检查 `data_policy.ai_may_generate_market_data == false`、`data_audit`、`data_warnings` 和每项数据日期。
- `data_audit` 为每次真实接口调用记录参数、返回字段、行数和规范化 DataFrame 内容的 SHA-256 指纹。该指纹不是原始网络响应哈希；缺少成功审计记录的数值不得作为事实引用。
- `source_fact` 是源接口事实；`deterministic_derived_metric` 是脚本按公开公式计算的派生值；`rule_based_policy_not_market_data` 是策略规则。三者不得混称。
- 禁止用 Mock、示例数据、硬编码行情、训练记忆、搜索摘要或其他基金/指数数据替代当前查询结果。
- 禁止模型在图表采样点之间补造数据；图表只能连接脚本返回的真实采样点。
- AKShare 版本必须为脚本锁定并验证的 `1.18.64`；版本不匹配时停止查询，而不是尝试兼容。
- 指数图表必须先判空 `charts.pe_ttm` 和 `charts.pb`，只使用非 `null` 指标的 `chart_series` 和 `reference_lines`；不得以零值代替缺失侧。
- `queried_at` 是查询时间，不一定是净值日期；优先引用各字段自己的 `date`。
- `data_warnings` 非空时，要在答案中显式披露。
- 单位净值、累计净值和场内价格口径不同；跨基金比较前先检查 `metric_basis`。
- `dca_plan` 是透明规则模板，不是历史最优参数，也不承诺降低亏损。
- 禁止把 PE 与 PB 分位平均成“综合估值”；二者经济含义不同，必须分别解释。
- 均值 ±1 标准差只作辅助参考；PE 分布通常非正态，优先使用中位数和 20%/80% 分位。
- 定投不输出固定 `0.5/1.5 倍`金额；具体金额必须基于用户预算和目标仓位。
- ETF 可用场内溢价率 `> 5%` 时，暂停当前场内渠道；等于 `5%` 不触发该硬阈值。
- 不生成虚拟定投回测。累计净值、前复权价不能直接冒充投资者实际可成交价格和账户收益。
- 历史表现不代表未来收益。没有用户风险承受能力、期限和仓位信息时，只提供观察条件。

## 常见问法

用户问“这个基金能买了吗、现在高不高？”：

1. 执行 `analyze`，不能只执行 `status`。
2. 若 `index_valuation.available=true`，继续执行 `valuation --index <index_name> --years 10`，使用完整历史 PE/PB 曲线和 `window_statistics` 中实际存在的 3/5/10 年窗口。
3. 先回答产品适配、持有体验、估值、趋势、回撤和溢价，再给定投动作。
4. 最后补充是否暂停申购、限购或不在交易时段。

用户问“现在适合买还是卖？”：

1. 执行 `analyze`。
2. 指数基金继续执行 10 年 `valuation`；主动基金不得用净值高低冒充估值。
3. 依次解释产品质量、持有体验、真实估值、历史位置、趋势、回撤、波动和溢价。
4. 给买入、卖出和定投三组条件式参考；卖出问题补问成本、仓位、持有期限和资金用途。

用户问“帮我挑一只”：

1. 执行 `compare`。
2. 先确认基金类别和跟踪标的是否可比。
3. 分别比较收益、回撤、波动、费率/限额和交易渠道，不输出伪精确总分。

用户问“给我看沪深300近十年 PE/PB 图”：

1. 执行 `valuation --index "沪深300" --years 10`。
2. 检查 `actual_source`、`data_warnings` 和两个 `charts` 是否可用。
3. 使用 `TRAE-dynamic-ui` 在 panel 中绘制双图和统计卡。
4. 正文说明当前 PE/PB、各自历史分位、实际区间和数据源口径。

## Agent 协作边界

本 Skill 是金融事实查询与确定性计算工具，不是完整金融 Agent。

Skill 内负责：

- 基金和指数精确解析、歧义拒绝及 AKShare 参数映射。
- 真实接口调用、Schema 校验、时效检查、内容指纹和失败审计。
- 收益、波动、回撤、历史分位、PE/PB 分位和 ETF 溢价的确定性计算。
- 透明、有限的规则化参考，以及稳定 JSON、错误码和数据警告。

外部 Agent、MCP 或 RAG 层负责：

- MCP 工具注册、鉴权、限流、缓存、超时隔离和调用日志。
- 用户风险画像、持仓成本、目标仓位、现金流、投资期限和会话记忆。
- 基金合同、招募说明书、定期报告、指数编制方案和监管规则的 RAG 检索。
- 宏观、新闻、公告及其他数据工具的编排，以及最终个性化报告和合规检查。
- 组合级风险、资产配置、再平衡和具体金额计算；这些不能只凭本 Skill 单次输出决定。

外部 Agent 不得让模型记忆、网页摘要或 RAG 文档覆盖本 Skill 返回的当前市场数据。RAG 只用于解释和文档事实；行情、估值、申赎状态及其日期必须以本 Skill 本次调用的审计结果为准。
