**项目角色：** Java 后端开发
**项目时间：** 【按实际时间填写】
**技术栈：** Java 21、Spring Boot、Spring MVC、MyBatis、MySQL、Redis、Docker、

**项目描述：**

面向基金、ETF、指数和股票等金融产品的查询与研究场景，建设统一后端服务，对接内部数据
计算服务和智能分析服务，为前端提供行情、估值、申赎状态、匿名互动及流式分析接口。
系统重点解决外部数据源响应较慢、数据口径不一致、部分接口失败以及金融数据需要保留来源
和审计记录等问题。

**核心职责：**

- 负责基于 Spring Boot 构建统一后端服务，集中承接金融数据查询、产品信息聚合、匿名
  互动数据管理、静态资源访问及流式分析接口，隔离前端与内部数据计算服务，明确接入层、
  产品数据和金融计算的职责边界。
- 针对多个独立金融数据接口存在阻塞等待的问题，使用 Java 21 虚拟线程和
  `CompletableFuture` 并行聚合指数、基金、ETF 与股票数据，并通过并发上限、分批提交
  及连接/读取超时限制下游访问压力，避免请求无限排队。
- 设计统一数据响应协议，完整保留数据来源、查询时间、数据警告、错误码及数据
  快照指纹；Java 侧只读取状态和展示元数据，原样返回金融数据，避免跨服务重复计算造成
  数值精度或业务口径变化。
- 建立可用、部分可用、数据过期和不可用等聚合状态，区分标的不存在、标的歧义、暂不支持、
  上游异常和数据过期等错误语义；单个数据模块失败时保留其他有效结果和原始失败原因。
- 基于 Redis Lua 脚本原子执行计数与过期设置，为金融查询和匿名互动接口实现固定窗口
  限流；Redis 异常时记录告警并降级放行，同时由下游并发隔离继续提供容量保护。
- 使用 MyBatis 和 MySQL 实现匿名投票及按钮反馈持久化，通过事务、联合
  唯一索引和写冲突重试保证同一客户端对同一业务主题只保留一条有效选择。
- 基于 Spring MVC 异步响应和 JDK `HttpClient` 实现智能分析结果的 SSE 流式转发，
  处理请求体大小限制、逐块输出、代理 Header 过滤和连接异常，保持长连接响应及时释放。
- 使用 Docker Compose 编排 Java、数据服务、智能分析服务、MySQL 和 Redis 等 7 个
  运行服务，仅暴露统一 Java 入口；通过后端单元测试、接口测试和前端自动化测试验证
  接口、并发、降级和部署链路。
