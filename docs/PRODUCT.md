# 产品范围

## 定位

一个面向个人研究的可信投研数据工作台：展示基金、ETF、指数和 A 股的结构化数据，并用
受约束的 Agent 解释已验证事实、比较差异和提出下一步研究问题。

产品辅助研究，不替用户做投资决策。

## 目标用户

- 需要研究基金、ETF、指数和 A 股的个人投资者。
- 希望在一个页面查看数据、口径、来源和限制的用户。
- 希望获得可追溯研究过程，而不是黑箱评分的用户。

## 产品形态

只继续推进网页端。CLI 保留兼容和开发调试，不再作为产品入口扩展。

产品只有两个一级模块：

1. **数据面板**：独立浏览结构化市场数据，不调用模型、LangGraph 或 MCP 协议。
2. **Agent**：通过 Skill、Fund MCP、Web MCP 和固定 LangGraph 回答研究问题。

两者共用同一套 Python 审计数据核心，但运行链路和界面入口独立。

### 当前已交付页面

| 页面 | 核心内容 |
| --- | --- |
| 数据面板入口 | 指数状态摘要和已接入/待接入分类入口；不是跨模块完整总览 |
| 指数 | PE TTM、PB、历史分位和完整历史双图 |
| 基金与 ETF | ETF 搜索、摘要、五联图、日期区间、趋势排序、warning 和审计引用 |
| 股票 | 待接入说明和 Agent 快捷入口 |

### 后续计划

- 主动基金产品档案、费用、评级、交易状态和非 ETF 详情；
- 股票价格/PE/PB 详情与研究动态；
- 跨模块完整总览；
- 通用页面上下文 `PageContext`；
- 审计通过后的基金和股票候选筛选。

## 核心场景

1. 不提问也能浏览结构化数据和实际更新时间。
2. 搜索标的并查看产品、风险、估值、交易状态和审计来源。
3. 在已接入表格中按同口径字段排序；候选筛选工具尚未实现。
4. 从列表或详情页调用 Agent 继续研究。
5. 区分市场事实、历史统计、公开观点和数据限制。

## 数据与 Agent 边界

- **数据工具**查询并校验市场事实，执行确定性计算。
- **Data API**把审计数据通过普通 REST 提供给 Go 数据面板，不依赖 Agent。
- **Agent**控制固定研究流程、工具调用、错误分支和输出门禁。
- **模型**理解语言并解释已验证事实，不决定金融数字、工具权限或最终放行。
- **网页**直接渲染结构化工具结果，不从模型文本提取市场数值。

净值、价格、PE、PB、收益率、波动、回撤、历史分位、交易状态和实体存在性只能来自
审计工具。缺失时显示无法确认，不允许模型或前端补数。

Web 文章可以作为非数值背景，但其中的数字不能成为市场事实。

## 展示原则

- 每个数据块展示实际 `as_of`、查询时间、状态、warning 和审计引用。
- T+1、盘中、过期和更新失败必须明确区分，不统一标记为“实时”。
- PE/PB 列表可展示当前值和分位，详情必须展示历史曲线。
- 指数详情分别展示 PE TTM 和 PB；个股详情分别展示价格、PE TTM 和 PB。
- 图表只连接工具返回的真实 `chart_series`，不插值、不前向填充、不补点。
- “参考 Wind”只表示信息组织和交互，不表示使用 Wind 数据或复制品牌界面。
- 不把 PE/PB、评级、收益和风险合成黑箱总分。

## 明确不做

- 涨跌、收益或目标价预测。
- 确定性买卖指令和自动交易。
- 当前不做组合分析、策略回测和复杂持仓管理。
- 当前不做登录、多端同步和永久会话。
- 当前不做 RAG、向量库、多 Agent 和长期记忆。
- 当前不引入 PostgreSQL、Redis 或消息队列。
- 不扩展成财经资讯门户、社交社区或完整交易平台。

## 新功能准入

新功能只有同时满足以下条件才进入开发任务：

1. 帮助用户分析标的或发现值得进一步研究的候选。
2. 数据和结论可以追溯到明确来源、日期和审计记录。
3. 不违反“不预测、不荐股、不自动交易”的边界。

实现状态和交付顺序只在
[投研数据工作台任务](tasks/TASK_research_dashboard.md) 和
[候选筛选任务](tasks/TASK_asset_screening.md) 维护。
