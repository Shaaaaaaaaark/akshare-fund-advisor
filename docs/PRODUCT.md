# 产品简述

> 本文用于和 AI 讨论产品方向与功能范围。讨论产品需求时优先参考本文，不展开技术实现。

## 一句话定位

一个面向个人研究的可信投研数据工作台：持续更新基金、ETF、指数和 A 股的结构化数据，
并提供受约束的 Agent，帮助用户浏览、筛选、比较和继续研究标的，但不替用户做投资决策。

## 目标用户

- 希望研究场内/场外基金、ETF、指数和 A 股的个人投资者。
- 希望快速了解一个标的，而不是自己在多个平台之间整理数据的人。
- 希望看到结论依据、数据来源和信息限制，而不是只得到一个评分的人。

## 产品形态

产品当前只推进**网页端**：以数据工作台为主，提供总览、列表、筛选、详情和研究动态；
Agent 作为全局入口和页面内研究助手，支持结合当前页面、筛选条件和已选标的继续提问。

网页参考数据型投研产品的信息密度，以及 GPT、Claude 的问答体验，但不复制其全部功能。
已经实现的 CLI 入口保留为兼容和开发调试能力，不删除，但不再作为产品形态继续开发或
增加功能。当前不做登录、账号体系或持久化历史；页面刷新或服务重启后，会话可以被清空。

## 核心使用场景

1. 用户在总览中查看数据更新时间、指数估值、基金状态、候选标的和最新研究动态。
2. 用户在基金、ETF、指数或股票列表中搜索、筛选、排序并进入单标详情。
3. 用户查看一个标的的产品信息、历史表现、风险、估值、交易状态和审计来源。
4. 用户选择一个或多个标的，让 Agent 解释当前页面、比较差异或生成下一步研究清单。
5. 产品补充研究机构、财经媒体和博主社区的公开链接，并区分事实、观点和限制。

## 网页主要页面

- **总览**：数据更新时间、数据源异常、指数估值概览、基金/ETF 风险提示、候选标的和
  最新研究动态。
- **基金与 ETF**：基金库、分类、搜索、筛选、排序和单标详情。
- **股票**：股票候选、估值、财务质量、行业比较和单标详情。
- **指数**：指数估值看板、PE/PB 历史位置、Wind 深度资料式历史双图、指数详情和关联基金。
- **研究动态**：研究文章、财经媒体和博主社区公开观点，保留来源、链接和发布时间。
- **Agent**：全局问答、当前页面问答、已选标的比较和筛选结果解释。

网页中的“持续更新”不等于所有数据都是实时行情。每个页面和记录必须展示实际的
`as_of`、查询时间、数据状态和审计引用；T+1、盘中或更新失败必须明确区分。

PE、PB 不能只展示当前值和历史分位：

- 列表和总览可以展示当前值与分位，用于扫描和排序；
- 指数详情必须展示 PE TTM、PB 两张完整历史曲线；
- 个股详情必须分别展示前复权价格、PE TTM、PB 历史曲线；
- 图表信息组织对标 Wind 深度资料，包括当前值、分位、均值、中位数、极值、分位参考线、
  可用观察窗口、来源和实际日期；
- “对标 Wind”只表示专业信息组织和交互，不代表使用 Wind 数据，也不复制 Wind 商标或
  专有界面。

## AI、Agent 和数据工具分别做什么

这三部分职责不同：

- **数据工具**负责回答“事实是什么”，例如价格、净值、估值、收益、回撤和产品信息。
- **Agent**负责控制研究流程，例如理解问题、选择分析步骤、调用数据、处理失败和检查答案。
- **模型**负责处理自然语言和非结构化信息，例如解释多个事实、比较不同观点和提出后续研究问题。

Agent 不是 AI 基金经理，模型也不能直接生成金融事实。产品中的 AI 应把可信数据整理成
容易理解的研究过程，而不是凭自身知识预测市场。

网页表格、图表和详情中的金融数值由结构化工具结果直接渲染，不先交给模型提取或改写。
Web 文章可以由模型总结观点，但其中的数字不能成为市场事实。

当前 Agent 已能完成工具编排、结果校验和输出门禁。启用模型后，模型可以基于已验证事实：

- 把宽泛问题整理成结构化研究问题。
- 汇总支持、反对和数据未知的证据。
- 比较工具事实与公开文章观点，但不混淆两者。
- 给出下一步值得继续核验的研究清单。
- 解释多个事实之间的一致、差异和数据限制。

模型不可用时，产品回退为确定性事实和基础研究问题。根据明确的用户期限、仓位和风险
承受能力调整解释重点仍是后续能力。

所有模型输出都必须使用可信工具结果，不能让模型决定金融数字、工具权限或最终放行条件。

## 已有功能

- 搜索并识别基金，遇到名称或份额歧义时要求用户确认。
- 分析基金的历史收益、波动、回撤、历史位置和持有体验。
- 查看基金类型、经理、费用、规模、资产配置和评级。
- 分析 ETF 的场内价格、净值估计和溢价风险。
- 分析指数和 A 股的 PE、PB 及其历史位置。
- 比较多只同类基金，并提示不具备可比性的情况。
- 查询申购、赎回、限额和交易状态。
- 搜索标的相关文章、研究报告、财经媒体及博主社区公开链接。
- 对多个可信事实做关联说明，同时明确相关性不等于因果。

## 下一步功能

- 把网页首页从纯聊天页升级为投研数据工作台。
- 实现总览、基金/ETF 库、指数估值看板和带完整 PE/PB 历史曲线的单标详情页。
- 在列表行、详情页和多选比较中接入页面上下文 Agent。
- 实现带来源、发布时间和分类的研究动态页。
- 按透明、可解释的条件筛选基金和股票候选。
- 输出每条筛选规则的通过、失败或数据未知状态。
- 对候选标的继续执行单标分析、同类比较和风险说明。
- 完善股票财务质量、行业同类比较和基金质量分析。

“优秀资产”不由 AI 主观打分，而由公开、版本化的筛选条件定义。

第一版工作台继续通过 MCP 获取并审计数据，使用有界进程内缓存。只有当列表规模、历史
快照和筛选需求稳定后，才评估 PostgreSQL；只有出现多副本共享缓存、任务锁或限流需求
后，才评估 Redis。

## 明确不做

- 不预测涨跌、未来收益或目标价。
- 不输出“必买、必卖、满仓、抄底”等确定性指令。
- 不执行自动交易。
- 不做黑箱综合评分或 AI 荐股排名。
- 不把历史表现当作未来表现。
- 不把相关文章或博主观点当作市场事实。
- 当前不做组合分析、策略回测和复杂持仓管理。
- 当前不做博主持仓展示、收益计算器、社交社区或完整交易平台。
- 研究动态服务于标的研究，不扩展成大而全的财经资讯门户。
- 当前不做登录、多端同步和永久保存对话。
- 当前不继续开发产品 CLI；已有命令只做兼容和调试维护。

## 产品原则

- **数据可信**：金融数值必须来自经过校验的数据源，缺失时明确说无法确认。
- **时效透明**：每项数据展示实际日期和状态，不用“实时”掩盖 T+1、过期或更新失败。
- **过程可解释**：结论应说明依据，筛选应展示具体规则。
- **事实与观点分离**：市场数据、产品解释、网络观点和信息限制分别表达。
- **数据优先、Agent 增强**：用户不提问也能浏览完整数据；Agent 负责解释和继续研究。
- **曲线优先于截面**：PE/PB 当前值必须放在历史曲线和实际观察区间中理解，不能只给一个
  截面数字或标签。
- **辅助研究，不替代决策**：产品帮助用户缩小研究范围，不承诺收益。
- **保持小而清晰**：优先做好单标分析和候选发现，不扩展成复杂金融平台。

## 判断新功能是否应该做

讨论新功能时，只需要回答三个问题：

1. 它是否帮助用户分析标的或发现值得研究的候选？
2. 它是否能提供可信、可追溯的依据？
3. 它是否违反“不要预测、不要荐股、不要自动交易”的边界？

前两个答案为“是”且第三个答案为“否”，才进入产品范围。
