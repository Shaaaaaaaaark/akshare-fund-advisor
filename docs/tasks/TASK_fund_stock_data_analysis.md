# TASK：基金与个股数据分析处理

> 状态：`已完成：P0、单标数据增强、Agent 交接和环境验证均已通过`
> 原则：先把基金、指数和个股的**单标的数据分析处理**做扎实；组合分析、回测和提醒暂缓。

## 1. 背景

当前项目已经有 `fund_analyze`、`fund_profile`、`fund_rating`、`fund_compare`、
`index_valuation`、`stock_valuation` 等工具。下一步不做复杂的组合体检或策略回测，
而是把这些工具返回的数据整理成更稳定、更清晰、更可复用的分析结果。

目标不是预测涨跌，而是让用户更快回答：

- 这只基金/ETF 的历史风险和持有体验如何？
- 它的估值、回撤、波动、费率、评级、资产配置分别说明什么？
- 这只个股当前 PE/PB 处在历史什么位置？
- 多只基金/指数/个股在同一口径下怎么比较？
- 基金产品、历史风险、跟踪指数估值和交易状态之间有哪些可验证的关联？

## 2. 范围

### 做

- 基金历史表现处理：收益、年化波动、下行波动、最大回撤、最长水下期、月度收益统计。
- 基金产品事实处理：费率、规模、基金经理、资产配置、评级、前十大集中度（可用则展示，失败明确标缺失）。
- 指数/ETF 估值处理：PE/PB 当前值、历史分位、P20/P80 区间、ETF 溢价。
- 个股估值处理：PE TTM、PB、前复权价格历史、估值分位与价格走势分离展示。
- 同口径比较：比较前先检查基金类型、份额、净值/价格口径、跟踪标的或业绩基准。
- 缺失与降级：数据缺失、过期、上游失败必须在输出中结构化标明。

### 暂不做

- 组合相关性、组合回撤、组合资产暴露。
- 因子归因、行业/风格暴露。
- 定投/再平衡规则回测。
- 最优权重求解、收益预测、股票评分排名。

## 4. 红线

- 所有市场数值只能来自已审计 AKShare 工具结果。
- 模型不得生成、补齐、插值、前向填充或改写任何数值。
- 净值历史位置不是估值；只有匹配指数后的 PE/PB 才是估值分位。
- PE 与 PB 分别解释，不计算综合估值分。
- 回撤、波动、历史分位都是历史统计，不预测未来收益。
- 上游失败只能回答“当前无法确认”，不能说“标的不存在”。
