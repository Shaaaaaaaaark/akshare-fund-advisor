# TASK：可审计基金与股票候选筛选

> 状态：`阶段 0 已完成：候选接口盘点和真实审计已完成，生产接入待实施`
>
> 产品定位：按用户可解释的确定性条件发现“值得进一步研究的候选”，不输出综合 AI
> 分数，不预测未来收益，不生成确定性买卖指令。

## 1. 目标

新增两个受控筛选能力：

- `stock_screen`：从沪深 A 股财务横截面中按质量、成长、现金流、财务安全和估值条件筛选；
- `fund_screen`：在同基金类型和同份额口径内按历史长度、收益、风险、费用、评级和披露
  配置筛选。

筛选输出必须逐项说明：

```text
passed_rules
failed_rules
unknown_rules
metric_basis
as_of
audit_ref
```

## 2. 非目标

- 不做收益预测、目标价、择时概率和自动交易；
- 不做因子挖掘、alpha、机器学习打分或黑箱排名；
- 不把 PE/PB、评级、收益和风险合成单一总分；
- 不比较不同基金类型、份额类别、净值/价格口径；
- 不用 Web、模型记忆或行业名称近似匹配补充市场数值；
- 不在本阶段实现组合优化和回测。

## 4. 阶段 A：股票候选池

- [ ] 新增股票筛选输入 Schema：
  - 报告期；
  - 市场范围固定为沪深 `0/3/6`；
  - 用户显式启用的规则；
  - 最大候选数量。
- [ ] 接入 `stock_yjbb_em`，声明并校验稳定字段。
- [ ] 拒绝未来公告日期、无效代码和非沪深代码。
- [ ] 不自动填充缺失 ROE、毛利率、收入增长或现金流。
- [ ] 同一报告期只保留唯一代码；冲突记录直接失败。
- [ ] 输出行业字段，但行业缺失时进入 `unknown_rules`。

## 5. 阶段 B：股票深度核验

- [ ] 接入 `stock_financial_analysis_indicator_em`。
- [ ] 接入资产负债表、利润表和现金流量表的最小字段集合。
- [ ] 同一指标必须绑定同一报告期和公告日期。
- [ ] 确定性计算：
  - 资产负债率；
  - 经营现金流/净利润；
  - 多期 ROE、收入和利润稳定性；
  - 商誉/总资产。
- [ ] 接入 `stock_zygc_em` 的报告期主营收入集中度。
- [ ] 不读取盈利预测作为当前事实。

## 6. 阶段 C：行业同类比较

- [ ] 优先使用 `stock_yjbb_em` 同表行业做财务横截面对比。
- [ ] 使用巨潮证监会行业归属和行业 PE 时，必须按行业编码精确关联。
- [ ] 分类标准、行业代码或日期不一致时拒绝比较。
- [ ] 巨潮接口增加有限重试，失败后输出 `UPSTREAM_ERROR`。
- [ ] 不恢复当前不稳定的东方财富行业板块目录/成分主路径。

## 7. 阶段 D：基金候选池

- [ ] 按基金类型分别调用 `fund_open_fund_rank_em`。
- [ ] 用基金目录确认基金代码、类型和份额类别。
- [ ] 对每行日期执行未来、过期和缺失检查。
- [ ] 历史不足时放入 `unknown_rules`，不得按零收益处理。
- [ ] 用本地净值序列重算收益、波动、回撤和持有体验。
- [ ] 合并 `fund_rating_all`，评级保持独立维度。
- [ ] 合并 `fund_manager_em` 时按基金代码聚合多位经理。
- [ ] 合并报告期行业配置，不表述为实时仓位。

## 8. 阶段 E：规则与输出

- [ ] 规则使用版本化 Pydantic Schema。
- [ ] 每条规则声明：
  - 输入字段；
  - 单位；
  - 比较方向；
  - 缺失语义；
  - 数据日期；
  - 审计引用。
- [ ] 阈值只能来自代码配置或用户输入，模型不能创建阈值。
- [ ] 输出保持通过、失败和未知三态。
- [ ] 只允许对同口径候选做确定性排序视图。
- [ ] 不生成综合质量分或“必买”标签。

## 10. 验收标准

- [ ] 股票池只含沪深 A 股规范代码。
- [ ] 基金池不跨类型、份额和指标口径混排。
- [ ] 所有市场数字均可反查接口、字段、日期和哈希。
- [ ] 缺失字段进入 `unknown_rules`，不补数。
- [ ] 上游失败不映射为“没有优秀资产”。
- [ ] 行业比较使用同一分类标准和同一日期。
- [ ] 不存在综合 AI 分数、收益预测或确定性交易指令。
- [ ] Skill、MCP、Agent、Docker 和真实接口冒烟测试全绿。
